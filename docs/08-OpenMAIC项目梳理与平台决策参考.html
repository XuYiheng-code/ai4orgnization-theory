DECISION BRIEF · 08 / 2026

OPENMAIC AUDIT / v1.0

从 OpenMAIC 出发，建设一套能运行课程的教学平台

这份报告回答三个问题：OpenMAIC 已经积累了什么；它与我们的课程平台还差什么；怎样复用它，而不把课程、评价和学生数据交给一个通用课堂生成器。

调研快照：2026-08-14 核对版本：OpenMAIC v0.3.2 交付形态：离线 HTML 决策参考 video-shotcraft：N/A（无视频交付）

建议决定

把 OpenMAIC 定位为互动课堂引擎，不把它当作整个平台。

我们的平台继续掌握身份、班级、课程内容、来源与证据、作业、研究项目和正式评价。OpenMAIC 负责把审核后的课程对象转换为场景，运行多智能体课堂、交互练习与 PBL，并提供编辑和导出能力。

推荐路线

先隔离试点，后包级集成
首轮只做一个样板单元，不直接覆盖 16 周课程。
01

课程平台是准本

教材、案例、量规和活动先在课程平台形成版本。OpenMAIC 生成的内容必须经过教师审核，才能发布为课堂场景。

02

OpenMAIC 是运行层

复用场景 DSL、渲染、编辑、播放、多智能体讨论、PBL 和导出。通过适配层与课程对象、学习记录连接。

03

正式评价留在人手里

测验和智能体评语只用于形成性反馈。正式成绩、发布和数据删除由教师或课程管理员确认。

04

先用公开或合成数据

在生产级身份、班级隔离和审计接入之前，不向 OpenMAIC 试点环境写入学生名单、成绩、私有作业或真实对话。

OpenMAIC 已经形成了什么

它已经从演示项目长成一套课堂内容生成与运行系统。积累主要在课程场景协议、课堂运行能力、编辑与导出、模型适配和工程测试，不在高校教学管理。

02 / 07

强项很清楚，边界也很清楚

OpenMAIC 解决的是“如何生成和运行一堂 AI 课堂”。我们的项目还要解决“课程由谁负责、学生属于哪个班、证据从哪里来、作业如何修改、谁确认成绩”。

内容积累不能外包给通用生成器

OpenMAIC 能把材料变成课堂，但《人工智能与组织理论》的课程判断、16 周结构、组织理论概念、案例、量规和教师观点仍要由课程团队编写和审核。平台的辨识度来自这套内容和学习方法，不来自“多智能体”这个功能标签。

03 / 07

进入正式班级前，先补六处缺口

这些缺口会直接影响学生数据、成绩和课程可信度，属于上线门槛。

P0

开发令牌不提供用户隔离

仓库明确说明公开编译的 persistence token 不是秘密，任何能打开页面的人都可以选择 learner key 读取或写入分区。正式运行必须换成真实会话验证，并从服务端身份派生班级和学生分区。

S5
P0

简答题故障时会自动给基础分

当前 quiz-grade 前端在评分接口失败时回退为约一半分。这个设计适合保持练习流程不中断，不适合课程正式成绩。我们应改成“待教师复核”，不得生成分数。

S6
P0

来源追溯还不是课程证据系统

材料解析和网页检索能帮助生成，但课程回答还需要段落级引用、可见范围、许可、知识库版本和拒答评测。学生研究中的现实证据与仿真证据也必须分开。

L1 · L2
P1

交互 HTML 仍需课程侧策略

OpenMAIC 已移除 iframe 的同源权限，能阻止生成脚本读取宿主 Cookie、localStorage 和 DOM；但沙箱仍允许脚本、表单和弹窗。正式环境还要限制外联域名、上传类型、资源大小和教师发布权限。

S7
P1

上游变化很快

仓库从 3 月到 8 月连续发布，6 月改为 MIT 并拆出 SDK，7—8 月又重做持久化和资产注册。集成时要锁定版本、保留适配层，并用兼容性测试验证升级。

S1 · S2
P1

开源许可变宽松，不代表所有资产都可直接用

主仓库当前是 MIT。依赖、模型、搜索结果、生成图片、声音样本和上传材料各有自己的许可与个人信息边界，仍需逐项记录。

S1 · S2
04 / 07

目标架构：课程平台掌握状态，OpenMAIC 提供课堂能力

两边通过明确的活动发布和学习事件契约连接。OpenMAIC 不直接写用户、班级、正式成绩或研究结论。

DEMO ONLY

直接 fork 整仓

最快看到完整课堂，但会把通用产品的身份、持久化、设置和 UI 一起背进来。适合演示，不适合作为长期架构。

PILOT · RECOMMENDED

隔离子应用 + 适配层

首轮把锁定版本的 OpenMAIC 运行在受控的 /lab 路径，只用公开或合成数据。课程平台负责启动活动并回收事件。

LONG TERM

按包集成

逐步引入 DSL、renderer、editor、generation 与 storage contract，把课堂能力嵌入主站。工作量更高，但产品边界最稳。

05 / 07

先用一个样板单元检验它

建议主题沿用现有项目设定：“AI 辅助公共服务与一线裁量”。它同时需要组织理论、多角色讨论、决策场景、证据评审和人机责任划分，可以检验 OpenMAIC 是否适合这门课。

01 组织问题 AI 建议与一线裁量发生冲突时，谁有权决定？
02 理论材料 有限理性、街头官僚、组织控制和问责。
03 场景讲解 教师数字入口讲解概念，引用课程资料。
04 多角色 PBL 窗口人员、主管、服务对象、审计角色共同决策。
05 学生产出 决策备忘录 + 3 分钟学术脱口秀提纲。
06 双重评审 量规证据检查 + 反例与替代解释。
07 教师确认 反馈发布、正式评价和优秀作品授权。

样板单元的验收对象

验收应看：学生能否把一个组织问题推进为有理论、有证据、有竞争解释的判断；平台能否保留人和智能体的分工、引用、修改和教师裁决。若这条学习链走不通，增加语音、3D 或更多智能体都没有意义。

06 / 07

十二周技术与教学验证路线

每一阶段都有退出条件。没有达到退出条件，不把更多课程内容和学生数据带入系统。

第 1—2 周

锁定版本，完成隔离复现

保存 v0.3.2 提交、许可证与依赖清单；用公开材料复现课程生成、播放、编辑和导出。记录服务器资源和模型成本。

退出条件

本地与测试服务器可重复部署；没有学生私有数据；主要功能有一份可复跑检查表。

第 3—5 周

制作样板单元

把课程对象映射为 DSL；按“公共服务与一线裁量”制作讲解、讨论、PBL 和学生产出，不开放自动发布。

退出条件

教师能编辑和发布一个版本；学生完成活动；主要结论能回到课程来源和过程事件。

第 6—8 周

接入平台身份与学习事件

实现签名启动、班级授权、活动版本、事件回传和审计。OpenMAIC 侧不保存正式成绩，测验故障转入教师复核。

退出条件

两个测试班级交叉验证不可见；事件带用户、班级、活动版本和时间；无公开开发令牌。

第 9—10 周

补齐来源与评测

接入课程知识库；区分课程资料、教师确认观点和模型推断；建立至少 30 个课程问题和拒答样例。

退出条件

课程团队冻结来源支持率、拒答正确率和不可接受错误；测试中不出现捏造来源。

第 11—12 周

小规模真实教学

选择一个小组或一次课堂活动试运行，观察任务完成、讨论质量、二次修改、教师工作量、故障与成本。

退出条件

学生完成一次“学习—产出—反馈—修改”；教师确认评价；完成备份恢复和数据删除演练。

07 / 07

需要课程团队确认的六项决定

勾选状态只保存在当前浏览器，便于讨论时记录；它不代表已经完成技术验收。
