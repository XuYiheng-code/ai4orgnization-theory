# 阶段 0 执行清单

阶段 0 的目标不是产出完整网站，而是消除会导致返工的分歧。课程团队、产品设计和技术人员围绕同一个样板教学单元协作，所有抽象方案都要在这个单元里走一遍。

## 一、样板单元

先选一个同时包含组织理论、现实组织问题和 AI 实验的教学单元。单元共用一个问题情境，分别设计一份现实研究任务和一份简化仿真任务。建议满足以下条件：

- 本科生不需要大量先修知识；
- 有一个清楚的组织问题；
- 可以安排角色、规则和智能体进行实验；
- 能形成可评审的学生作品；
- 有合法可用的理论文献与案例材料。
- 能区分现实证据、模拟证据和派生分析，并形成可复核研究包。

样板单元使用 [教学单元模板](../content/course/unit-template.md) 编写。平台首页、知识问答、作业流程和数字 IP 都先围绕它设计。

## 二、工作包与产出

| 工作包 | 负责人 | 阶段 0 产出 | 完成标准 |
|---|---|---|---|
| 课程设计 | 待定 | 课程定位、学习成果、大纲、样板单元 | 能说明学生学完后会做什么 |
| 内容建设 | 待定 | 教材样章、案例、作业、量规、来源清单 | 一个单元可以独立开课 |
| 知识库 | 待定 | 两个知识域的首批条目、30 个评测问题 | 每个问题有期望来源或拒答条件 |
| 产品设计 | 待定 | 首页、学生本周页、智能体页、教师复核页原型 | 五名目标用户能完成核心任务 |
| 智能体设计 | 待定 | 三个 P0 角色、权限、提示词和拒答规则 | 在样板问题上通过人工评测 |
| 研究工作台 | 待定 | 问题卡、证据表、假设、设计、分析产物、审核和研究包 | 一个样板项目能由另一组复核 |
| 双路径教学 | 待定 | 一份现实研究任务、一份简化仿真任务及共同量规 | 学生能解释两类证据的关系和边界 |
| 数字 IP | 待定 | 角色设定、三个方向草图、使用场景 | 课程团队选定一个方向继续深化 |
| 技术与基础设施 | 待定 | 环境清单、部署图、数据模型草案、风险表 | 测试域名可用，关键依赖有负责人 |
| 教学治理 | 待定 | AI 使用规则、成绩确认、数据与作品授权流程 | 教师能解释每项责任由谁承担 |

## 三、建议顺序

### 第 1 轮：先定课程

确认课程名称、对象、学习成果、考核方式和样板单元。同步整理已有资料，不做页面视觉稿。

### 第 2 轮：走完学习链

用样板单元模拟一名学生从进入课程、阅读材料、向智能体提问、登记证据、提出假设、提交研究设计、上传分析产物到收到反馈的过程。记录每一步需要的内容、数据和教师决定。

### 第 3 轮：验证内容与智能体

把样章和来源做成小型知识库，用 30 个问题测试引用、拒答和概念解释。用三份不同质量的作业样例测试作业教练和评审流程。

### 第 4 轮：确定原型和技术边界

根据前面的真实内容绘制关键页面。课程团队先评审信息和流程，再讨论视觉风格。技术人员据此确认数据模型、接口、部署和预算。

### 第 5 轮：开发准备评审

逐项检查 [MVP 范围与验收](02-MVP范围与验收.md) 中的进入开发门槛。未确认的问题保留为明确风险，不用模糊措辞带过。

## 四、会议建议

每次讨论只处理一种决定，并在会后更新文档：

1. 课程决定：课程教什么，学生交什么；
2. 产品决定：学生和教师如何完成任务；
3. 智能体决定：模型能做什么，何时必须交给人；
4. 技术决定：数据放在哪里，怎样发布和恢复；
5. 品牌决定：课程希望被怎样识别和记住。

决定采用 ADR 或简短会议记录保存。没有负责人、验收标准和生效日期的结论不进入开发任务。

## 五、阶段 0 退出条件

- 课程团队认可一个样板教学单元；
- 三类 P0 智能体的边界已经写清；
- 关键页面原型通过目标用户走查；
- 30 个知识库问题和三份作业样例完成试测；
- 一个现实研究样例、一个简化仿真样例和研究包完成复核；
- 数据、成绩、数字人和作品授权责任有明确负责人；
- MVP 的 P0 范围、技术路线和部署预算获得确认。
