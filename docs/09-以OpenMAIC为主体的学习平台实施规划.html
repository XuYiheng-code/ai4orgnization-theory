组 人工智能与组织管理LEARNING PLATFORM · REVISION 01
方向调整三阶段系统关系学习场景当前执行
Decision brief · 2026.08.14

从考核平台
转向学习平台

以 OpenMAIC 为新的教学平台主体。学生从课程材料或自选文献出发，生成课堂、参与多智能体讨论、留下学习过程，并把优秀成果带回课程知识库。

查看实施路线 OpenMAIC 官方仓库
本次决定重新开始，但保留课程公共入口
  1. 01教学平台栏目改为 OpenMAIC，不再以作业审核工作台作为首页。
  2. 02第一阶段完整部署官方版，先取得功能基线，再做课程定制。
  3. 03课程主页、大纲和知识库继续存在，作为学习内容与共建成果的公共入口。
  4. 04模型密钥只存服务端；学习记录、文件和发布状态进入可审计数据库。
01 / 转向

平台的主任务变了

审核与给分可以保留，但不再组织学生的主要路径。平台首先要让学生进入材料、提出问题、生成课堂、参与互动并沉淀自己的理解。

退出主线

提交—审核—给分

  • 学生围绕教师布置的作业行动
  • 平台价值集中在检查与评价
  • 学习过程大多留在最终提交之外
→
新的主线

材料—生成—互动—共建

  • 教师材料与学生自选文献都可成为课堂起点
  • 多智能体课堂承担讲解、讨论、模拟与项目学习
  • 过程记录和优质成果回流课程知识库与课程体系
P / 01

学生可发起

学生可以上传合规材料、自选主题并生成个人课堂，不必等待教师布置任务。

P / 02

教师可编排

教师把课程目标、参考文献、课堂活动和生成内容编排成每周学习路径。

P / 03

过程可追踪

保留上传、生成、提问、修改、互动与发布记录，用于反馈、研究和内容治理。

P / 04

成果可共建

教师从学生成果中择优，取得授权后发布到前台，补充课程知识库。

02 / 路线

三阶段实施，不把定制提前塞进部署

每一阶段先达到可验证的退出条件，再进入下一阶段。这样既能紧跟上游，也能知道问题出在官方能力、模型配置还是课程改造。

现在执行
本地化部署与官方功能复现

先让官方 OpenMAIC 在本机完整运行

锁定官方版本，安装依赖，接入阿里云百炼的 OpenAI 兼容接口；对照 open.maic.chat 核验课程生成、编辑、播放、测验、互动场景、PBL、多智能体讲解、语音、导入与导出。课程网站的“教学平台”入口改为本地 OpenMAIC。

官方仓库与许可证留档
Node / pnpm / 浏览器依赖检查
模型 Base URL、模型名与密钥配置
公开或合成材料生成测试
桌面端与移动端浏览器核验
失败项、外部服务与资源需求清单
退出条件

本地地址可稳定打开；模型调用成功；官方仓库可提供的主要功能逐项有验证结果；课程网站入口能够进入本地课堂；密钥未进入前端、仓库和日志。

部署后启动
课程改造与学习数据沉淀

把通用课堂改成这门课的学习环境

在官方基线上增加课程内容连接、视频下载、学习活动记录和教师后台。此阶段先做课程网站，不急于同步小程序。

生成视频下载与版权提示
课堂内容关联周次、概念与文献
教师材料与学生材料分区
上传、生成、交互和修改事件入库
教师审核、授权与前台发布
模型调用、费用、失败与版本审计
退出条件

一篇指定文献和一篇学生自选文献都能完成“上传—生成—学习—留痕—择优发布”；教师后台能够复核全过程；撤回和删除可以追踪。

课程版稳定后
生产上线与小程序同步

封装独立版本，与网站和小程序共同上线

建立真实账号、权限、对象存储、备份和运维方案。网站承担完整创作与教师后台，小程序承担进入课堂、继续学习、提醒和轻量互动。

用户名、密码与可选统一登录
个人空间、班级与教师权限
文件、课堂、对话与作品数据库
内容审核、授权、发布和撤回
服务器反向代理、监控与备份
小程序接口、隐私说明与审核发布
退出条件

不同用户数据严格隔离；教师能查看被授权的学习记录并择优发布；网站与小程序读写同一套服务；备份、恢复、删除和版本升级经过演练。

开源版与官方托管站需要分开验收：2026 年 8 月 14 日实测 open.maic.chat，托管站还包含登录、公开课程“发现”页、浏览量与互动数据。v0.3.2 开源仓库提供完整的课堂生成、编辑和播放能力，但没有托管站对应的账号与公共课程服务。第一阶段复现开源功能；账号、作品广场和后台数据按第三阶段自建，不能把“仓库部署成功”写成“托管站全部复刻”。

03 / 关系

OpenMAIC 是教学平台主体，课程站负责组织与发布

这里不再把 OpenMAIC 当作外围插件。它直接承担课堂生成和学习互动；课程站负责把这些课堂放回周次、文献、知识库和师生共同建设的结构中。

04 / 场景

围绕学习发生的四条主路径

这些路径共同决定后续数据库和界面。先定义学生怎样学，再决定后台需要记录什么。

教师指定文献

文献变成交互课堂或课程 vlog

  1. 教师选定合法材料并设置学习目标
  2. OpenMAIC 生成讲解、测验、互动和讨论
  3. 教师编辑、发布到对应周次
  4. 学生学习、提问并留下过程记录
学生自主探索

每位学生都能发起自己的课堂

  1. 学生上传自选文献或输入问题
  2. 平台提示来源、许可与隐私边界
  3. 生成个人课堂并与智能体互动
  4. 学生整理收获并决定是否申请公开
课程共建

优秀成果回到公共知识库

  1. 系统记录课堂版本、引用和作者
  2. 学生主动授权教师查看与发布
  3. 教师审核事实、版权和课程关联
  4. 发布到文献、概念或周次页面
个人数字分身

从学习记录形成可控的智能体角色

  1. 学生选择可用于分身的材料和偏好
  2. 分身只在明确授权范围内参与讨论
  3. 所有发言标明机器生成并保留来源
  4. 学生可暂停、修改或删除分身资料

06 / 底线

学习平台也需要明确底线

从考核转向学习，不意味着放弃责任边界。相反，学生可以上传和生成更多内容后，来源、授权和数据隔离更重要。

密钥与账号

模型密钥不进入浏览器。生产环境使用真实会话、最小权限和用户数据隔离，不能沿用开发令牌。

材料与版权

上传时记录来源、许可和可见范围；公开视频、声音克隆和数字分身需要单独授权。

生成与发布

生成内容默认属于个人学习空间。公开发布必须经过学生授权和教师审核，并标注作者、来源与生成过程。

学习与评价

自动测验和智能体反馈用于形成性学习。若以后恢复正式成绩，仍由教师确认，模型故障不能自动给分。

记录与研究

教学运行所需记录与课程研究数据分开。用于研究分析前需告知用途、去标识并按要求取得同意。

仿真与现实

多智能体讨论和角色扮演能帮助形成问题与解释，但不能单独证明现实世界中的因果关系。
