# ADR-001：平台边界与技术路线

状态：提议  
日期：2026-08-07
更新日期：2026-08-09

## 背景

项目同时包含公开课程主页、在线教材、数字人问答、教学平台、社会科学研究工作台、多智能体反馈、两个知识库和数字 IP。若按页面逐个开发，身份、内容、数据和智能体能力会互相复制；若一开始拆成很多服务，当前团队又会承担过高的部署与维护成本。

## 决策

### 1. 产品分成公开区和教学区

公开区允许匿名访问，只使用公开课程内容。教学区需要登录，保存班级、作业、成绩、对话和教师私有材料。两者共用品牌、内容模型和智能体运行时，但不共用默认数据权限。

MVP 在同一主域名下使用路由分区：`/`、`/learn`、`/teach` 和 `/admin`。这减少跨站身份和导航问题，后续仍可把教材或教学平台独立部署。

### 2. 首期采用模块化单体

使用一个 Web 应用和一个 FastAPI 后端。后端按身份、课程内容、知识库、智能体、班级、作业、评审和审计划分模块。模块之间通过明确的数据模型和服务接口调用，不在第一阶段拆微服务。

### 3. 课程内容使用结构化文本保存

大纲、教材、案例模板、作业模板和量规模板保存在版本控制中的 Markdown/MDX 或 Quarto 源文件。业务数据库保存班级对内容版本的引用、班级专属设置、发布状态、权限和运行数据。内容发布后生成版本号，知识库索引引用该版本。

MVP 的教师工作台不直接改公开教材。教师选择已发布版本，调整本班截止时间、说明和可见范围。以后增加 CMS 时，网页编辑也必须生成可审核、可回退的内容版本。

### 4. 使用 PostgreSQL 统一业务数据和向量索引

首期使用 PostgreSQL 与 pgvector，减少独立向量数据库的运维。文件放入 S3 兼容对象存储。以后只有在数据量、查询延迟或独立扩缩容需要明确出现时才更换。

### 5. 正式评价保留人工确认

智能体生成量规证据、分项建议和反例，不直接决定正式成绩。系统记录模型意见与教师修改，学生只看到允许发布的反馈。

### 6. 数字人与智能体能力分离

数字 IP 是统一交互入口和品牌角色，课程导航、理论问答、作业教练等能力作为独立服务。更换形象不应改变教学规则，更换模型也不应改变角色权限。

### 7. 研究状态由平台保存，执行引擎可以替换

研究问题、来源与证据、主张、假设、研究设计、分析产物、仿真实验、执行轨迹和审核记录属于平台数据。模型、Skill、代码执行环境或后续接入的 AgentSociety 只执行受限任务，不能成为研究状态的唯一持有者。

研究模块首期仍放在模块化单体中，但使用独立对象协议和服务边界。清华项目学习仓中的本地文件原型只作为协议参考，不直接接入多人教学环境。课程平台重新实现身份、班级权限、事务存储、密钥管理和数据保留规则。

## 结果

这一方案能较快支持首个班级，部署和备份也相对简单。代价是 Web 与 API 的内部模块需要严格约束，否则模块化单体会逐渐变成难以维护的大应用。

公开教材如采用 Quarto，可能形成独立构建流程。主站需要统一导航、搜索和问答入口，避免学生感觉在多个互不相关的网站之间跳转。

## 重新评估条件

出现以下任一情况时重新讨论架构：

- 单个服务需要独立扩缩容；
- 多门课程由不同团队独立运营；
- 知识库规模使 PostgreSQL 检索无法达到目标延迟；
- 教材发布与主站发布互相阻塞；
- 学校要求接入统一身份认证或指定数据平台；
- 审计、安全或合规要求需要物理隔离。
